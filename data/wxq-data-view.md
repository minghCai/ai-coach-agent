## 模式区分（万象大赛 vs 钻石狂潮）与数据版本分区

**响应体里没有任何模式字段**，模式完全由请求参数决定。站点最新构建（`assets/seo-DqnkTdOA.js`）中：

```js
const $1=[{value:"2",label:"万象大赛"},{value:"4",label:"钻石狂潮"}], Ja="2";
const Fe="v1";
function ti(t,a,e,n){
  const s=new URLSearchParams({time:String(t),version:a,gameType:e});
  return e==="4"&&n&&s.set("subModeName",n), s.toString();
}
// /wzwxq/rankings/heroes | equipment | commanders 均走 ti()；另有 /wzwxq/explore（POST，参数同形 An()）
```

| 参数 | 取值 | 默认 |
|---|---|---|
| `gameType` | `2`=万象大赛　`4`=钻石狂潮 | **`2`** |
| `subModeName` | 仅 `gameType=4` 有意义：`大师场`/`精英场`/`标准场`/空=不限 | 无 |
| `time` | 天数窗口 | — |
| `version` | **数据版本分区 id**（实测形如 `v261008`，随站点发布滚动，非普通语义版本号） | 不传=服务端回落最新分区 |

### 数据版本分区（钻石狂潮能否采到的真正原因）

`version` 决定读哪个数据分区，而**并非每个分区都含钻石狂潮**。线上实测（2026-10-14，本站出口，`time=7`）：

| `version` | `gameType=2` 万象大赛 | `gameType=4` 钻石狂潮 |
|---|---|---|
| `v1`（旧分区） | `code=1`，1,137,509 场 | **`code=42000`「该条件下数据样本过少」** |
| 当前分区（如 `v261008`）／不传 | `code=1`，344,839 场 | **`code=1`，261,030 场** |
| `v261001`／`v2`／`v0` 等不存在的分区 | — | `code=42000`「该版本数据暂无，请切换其他版本」 |

- 旧分区 `v1` 只沉淀了万象大赛样本，其中没有钻石狂潮 → **这才是长期采不到钻石狂潮的真正原因**；
  与 IP 封禁、限流、参数废弃、模式无数据均无关（这几种旧结论均已推翻）。
- 不传 `version` 时服务端回落到最新分区，两个模式都有样本；三个端点（heroes/commanders/equipment）均正常返回。
- 因此采集端 `collector/fetch-meta.mjs` 的 `buildEndpoints` **刻意不带 `version`**。`time=7` 下钻石狂潮约 26.1 万场，
  `subModeName=大师场` 为它的子集（约 13.9 万场）。

## 阵容榜（lineups）

端点：`POST /wzwxq/lineups/search`（用 GET 返回 405），body `{time:7, gameType:'2'|'4', page, pageSize:20}`；
仅 gameType=4 且为具体场次时附 `subModeName`；**刻意不带 version**（与榜单同口径）。

落盘：`data/meta/<YYYY-MM-DD>/<slot>/api/lineups-{1,2}.json`（每页各存一份原始响应，不合并不改写）。单页 `pageSize` 上限 20。

规模（time=7，2026-10-14 实采）：万象大赛 **32 套**（sampleCount 344,959）、钻石狂潮·大师场 **22 套**（sampleCount 140,058）→ 固定取 2 页即可覆盖。

**阵容 = 一组英雄的固定组合**，`lineupKey = 阵容人数|英雄id|…`（英雄 id 升序）。万象大赛榜首示例：

| lineupKey | 英雄 | 常用棋手 | 场次 | 登场率 | 平均名次 | 登顶率 | 前三率 | 变体数 |
|---|---|---|---|---|---|---|---|---|
| 7\|1311\|1361\|1441\|1541\|1751\|1861\|5131 | 李白/武则天/程咬金/花木兰/钟馗/太乙真人/上官婉儿 | 嬴律/庄小鱼/明先生 | 18761 | 32.6% | 3.0849 | 23.0% | 60.4% | 24 |

每条记录还带 `coreHeroes`（核心英雄子集）与 `recommendedUnits`（逐英雄出装推荐，`recommendationType` 取 `three_item`/`single_item`/`none`）。
`appearanceRate` 是该阵容在阵容榜内的登场率，不等于单卡场次占比。
